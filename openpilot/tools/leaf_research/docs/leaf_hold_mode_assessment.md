# 保持状態ビットの役割と再発進周辺信号の検証

追記：停止中ブレーキによる解除の2例には装置のCANCEL送信要求が介在していた。純正ブレーキ操作だけの解除とは扱わない。また1181秒付近の停止中有効化は公式の操作条件との相違が残る。訂正と根拠は leaf_2022_model_and_cancel_findings.md を参照。


対象はe-Pedal ONの59・5aと、OFFの5c。今回は1C3 bit2の指令／応答という仮説を、全走行中の立ち上がりと、1CB候補値との関係で検証した。既存の受信ログの追加解析であり、実車送信は行っていない。

## 1C3は数値と状態を分けて扱う必要がある

3ルート計351,022フレームで、byte5 bit7は制動の10bit数値が正であることと完全一致した。一方byte5 bit2はその条件と独立している。

|ルート|数値ゼロ・bit2 ON|数値正・bit2 OFF|
|---|---:|---:|
|59|4,713|85|
|5a|2,762|57|
|5c|14,881|409|

したがってbit7とbit2を同じ有効信号として扱えない。数値による制動、数値ゼロでも状態が継続する保持、状態bitが立つ前の制動開始を分けることが必要。これは受信パターンの分類であり、各組み合わせの送信時の効果まで確定したものではない。

## bit2は単純な『圧力が出た』信号では説明できない

5cでbit2が立った40回を調べた。36回は1C3の正の数値が始まってから約90～120ms後、2回は約49ms・60ms後、2回は数値と同時にONだった。

同時にONの2回は152.483秒と402.822秒。1CB第2の11bit値はその時点でゼロで、約29～30ms後に正になった。このフィールドがブレーキ応答候補であることを前提にすれば、bit2が必ずその立ち上がり後に出るという説明は不成立。

逆に大多数では数値・1CBの応答候補が先に出てbit2が後から立つ。bit2が必ず制動開始前に必要という説明も不成立。単一の固定待ち時間や、単純な数値閾値に置き換える根拠も不足している。

1CB全64bitを-100～+100msの候補遅延で照合したが、1C3 bit2をそのまま説明する単独bitは見つからなかった。最上位のF1も約0.60で、保持候補bitは約0.57。これは探索的な関連指標であり、安全性・制御性能の指標ではない。1CBの保持候補bitは保持場面だけで立ち、1C3 bit2は走行制動でも立つという違いが大きい。

現時点ではbit2を、制動制御の継続状態・許可・応答の反映などを含む未知のモード候補として扱うのが妥当。指令なのか応答なのかという問いは未決着。解除時に1CBより約10～20ms遅れることだけで応答と断定することもできない。

## 2D4・28Fは独立した保持解除指令の有力候補から優先度を下げる

対象はbus1 2D4 byte0 bit7と、bus1 28F byte2 bit6。両方を全走行で2B0有効bitと直前値比較した。比較フレームの鮮度は30ms以内。

|ルート|2D4比較数|不一致|28F比較数|不一致|
|---|---:|---:|---:|---:|
|59|43,454|2|43,444|2|
|5a|31,666|0|31,661|0|
|5c|100,430|9|100,406|9|

両候補は保持解除場面だけでなく走行全体で2B0有効状態とほぼ一致した。独立した保持解除機能という解釈より、走行要求の有効性に関連する解釈を優先する。ただしどちらかが受信側の許可に必要という可能性は残り、送信時に省略してよいという結論ではない。不一致には信号の更新周期・直前値比較による差が含まれ得る。

## 実装案への反映

数値ゼロと全機能解除を同一視しない状態機械が必要。候補となる段階は、通常走行要求、数値による制動開始、モードbitを伴う制動、保持、走行要求による保持解除、ペダル介入による引き継ぎ。

ただしこの段階分けは観測を整理する枠組みであり、どのbitをこちらから送れば移行するかはまだ不明。特にbit2を保持し続ければ保持できるという仮説と、別の保持状態を反映してbit2が立つという仮説は両方残る。

次の調査では、保持成立を示す1CB候補bitの立ち上がり約200ms前後を中心に、状態変化を持つ複数bitや数値フィールドを比較する。単独bitだけで説明しようとする探索から、要求と応答の組み合わせへ進む必要がある。ブレーキで停止してからACCを有効にした1181秒付近は、走行制動なしで保持を成立させており、特に判別力が高い。
