# セッション予備試験の実装状況

2026-11-03、experiment/leaf-longitudinal。

## 実装した範囲

session_probe.pyに、専用通信部から呼ぶ一回限りの試験処理を実装した。実機通信部や自動起動への接続はまだ行っていない。

- 送信内容は候補セッションへの移行と通常セッションへの復帰の2種類だけ。通信停止命令や駆動・制動要求は扱わない。
- 対象車種・記録済みFW・診断段階・Panda設定・Pレンジ・速度ゼロ・ブレーキ保持・ACC未使用・入力鮮度などを検査する。
- 試験前に対象2信号が揃って継続していることを確認する。
- 移行要求の送信失敗、否定応答、応答なし、途中例外、操作条件の変化でも復帰を試みる。
- 復帰確認には肯定応答に加え、対象2信号の両方が整合した形式で継続していることを要求する。
- 再実行を拒否し、通常制御の開始許可は常にfalse。成功とされた場合も人の確認を必要とする結果を返す。

## 検証

既存の記録・状態管理と合わせて25件のテストが成功。今回追加分は、上記の拒否条件と復帰分岐、送信が2種類だけであること、片方の信号だけの復帰では成功にしないことを模擬通信で確認した。Ruffのチェックも成功。

模擬通信の成功は、対象ECUの応答や副作用の検証ではない。今回の閾値・待ち時間は試験用の仮値。

## 起動時の接続に残る実装

起動時のCI.initからControlsReady設定までが既存の診断段階。ここでcardが所有する送信主体を利用する設計が候補で、通常運転中に別の送信プロセスを増やす構成は避ける。

実機接続部は、試験待機中にもCAN・車両状態・Panda設定を更新し、全CANと要求・応答を永続記録する必要がある。また、復帰未確認時にプロセス再起動を挟んでも通常制御へ進まない永続的な抑止を設計する。単にfinallyがあるだけではプロセス強制終了や電源断時の復帰保証にはならない。

この接続部は未実装であり、現時点では実機試験を開始できない。commaへの導入・診断要求の送信・設定変更は行っていない。追加の乗車やREADY維持はまだ不要。
