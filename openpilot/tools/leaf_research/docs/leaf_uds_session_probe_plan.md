# 75D UDS診断セッション予備試験

2026-11-03。送信停止・制御要求を含まない、一度限りの停車試験を準備する。自車でのセッション対応は未確認。

## 1回のREADYで行う手順

1. P・速度0・ブレーキ保持・アクセルOFF・ACC OFF、専用診断通信所有、Panda状態、通常CANの継続を確認。
2. 75D/bus0へ22 F1 88を1回送り、77D応答の識別値が今回取得した284E76WK2Eであることを確認。必要なISO-TPフロー制御は最大1回。
3. 標準UDSの通常セッション要求10 01を1回送信。新鮮な50 01応答と期待する6バイト形式・タイミング情報を確認。
4. 通信を約0.2秒観測し、対象2信号と事前20Hz以上のバス/ID群の継続を確認。通常セッションが拒否・無応答・想定外形式なら拡張へ進まない。
5. 条件を満たした場合だけ、拡張診断セッション10 03を1回送信。肯定応答なら約0.2秒観測。
6. 拡張要求を送った可能性があれば、拒否・無応答・例外でも通常への10 01を1回優先送信。復帰前の受信処理やブレーキ条件確認を挟まない。診断通信の所有と新鮮なPanda診断状態の確認は省略しない。
7. 50 01と約0.5秒の対象信号・周辺高頻度通信を確認。全結果で通常制御へ移行せず、操作員がOFFにして警告と記録を確認するまで抑止を保持する。

最大の追加送信は識別読出し1回＋条件付きフロー制御1回＋通常/拡張/通常の3回、合計5 CANフレーム。通常起動時のFW照会は別に存在する。各応答待ちは最大0.5秒。拡張後の約0.2秒は肯定応答後のホスト観測時間であり、ECUの状態継続時間を保証しない。

## 応答の扱いと保護

- UDS一般仕様の通常1・拡張3という意味と応答解析は[udsoncanのDiagnosticSessionControl資料](https://udsoncan.readthedocs.io/en/latest/udsoncan/services.html#diagnosticsessioncontrol-0x10)とローカル定義を照合。日産の当該ECUで対応している証拠ではない。
- 今回は6バイト肯定応答を要求する。別形式に応答しても推測で受理せず、先へ進まない。応答中P2が0より大きく500ms以下、P2*が正であることも先へ進む条件。
- 遅れて届いた別セッションの肯定応答は記録して待ち続け、通常復帰の肯定応答と取り違えない。古い受信時刻の応答も採用しない。
- 送信部でも新鮮な識別値・最初の通常セッション肯定応答・一度限りの拡張・復帰回数を独立に制限。
- 復帰送信はブレーキ条件変化・ログ記録失敗・受信失敗で妨げない。通信所有を失った場合やホスト自体が停止した場合の復帰までは保証しない。

## 含めない操作・未検証事項

送信停止0x28、送信再開0x29、リセット、DTC消去、Tester Present、セキュリティ解除、書換え、プログラミングセッション、加速・制動・操舵要求は含めない。

通信継続と肯定応答は全ADAS機能の正常性やDTCなしを証明しない。自動セッションタイムアウト、ホスト停止時の挙動、AEB・操舵・走行中の挙動は未検証。セッション変更だけでも制御への影響があり得るため、停車中の別試験として扱う。

## 検証と現在の状態

PCで全108件の模擬試験、Ruff、差分チェックに合格。通常拒否・無応答・異常タイミング・識別不一致で拡張を阻止し、拡張後の受信例外・輸送例外・ブレーキ解除・記録失敗でも復帰を優先する試験を含む。実車の対応確認ではない。
