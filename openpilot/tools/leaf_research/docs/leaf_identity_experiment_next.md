# 識別情報調査：既存ログ監査と次の限定実験

2026-11-03。新規の実車送信なし。車両は日本仕様ZE1 e+ G、車台番号20万番台以降（ユーザー申告）。

## 今回の観測

59、5cのsegment 0の生ログを再解析した。CAN上のISO-TP応答を再構成し、carParamsに保存された値と独立に比較した。

- 0x707への21 83に対応する0x727の61 83応答は、両ルートとも同じ24バイトの6WK6ADB識別値。carParamsの値と一致した。
- 各ルートでbus 0/2に各2応答、bus 1に1応答。0/2転送やゲートウェイ経路を含むため、件数をユニット数と解釈しない。
- この対象の再構成では欠落・順序不整合の連続フレームは0、未完了メッセージは0。
- 起動時sendcanの11bit 0x700–0x7FF範囲の単一フレーム要求を列挙した。0x75Dは照会先に含まれていない。これは全期間・全アドレスの診断探索ではない。
- 他に保存された分類はEPS、ABS、gateway。0x18DAD0F1のgateway識別値は284U26WK3B。これをADAS品番と取り違えない。
- 0x707への既存要求は10 81、10 DA、21 83、22 F1 88、3E 00。新しい資料なしにこれらを再試行する価値は低い。

数値と応答：leaf_recorded_identity_inventory.json、leaf_recorded_identity_reassembly.json。後者の識別値はleaf_recorded_adas_firmware.jsonと照合済み。

## 次の限定実験案（未実装・未実施）

一次資料の別年式ZE1にADASとして載る0x75Dを、識別読み出しの候補とする。
資料：https://i.blackhat.com/Asia-25/Asia-25-Evdokimov-Remote-Exploitation-of-Nissan-Leaf.pdf （107ページ）

これは2022年の同アドレスを証明しない。資料中のアクチュエーター操作例は再現しない。

1. 車両状態・通信環境を改めて確認する。P、駐車ブレーキ、ブレーキ保持、速度0、ACC OFF。実行時の電源状態と操作員の準備を確認する。
2. 既存の一度限り起動ゲートと別の識別試験として実装・検証する。既存の停止試験無効化は解除しない。開始前に全受信CANと送信記録を保存する。
3. 通常セッションのまま、0x75Dへの21 83を一度だけ候補にする。識別読出しサービスとしての根拠は既存0x707実測。ただし0x75Dでの対応は未知。まずbus 0での計画を評価し、bus 1等への自動再送やアドレス走査は行わない。
4. 多重フレーム応答ならISO-TPのフロー制御送信も必要。この追加送信を含めて許可対象・回数・時間を制限する。返信候補0x77Dは日産の既存+0x20関係からの仮説であり、資料で確定していない。全受信を記録し、適合しない応答へ勝手にフロー制御を送らない。
5. セッション変更、Tester Present、停止、リセット、DTC消去、書換え、入出力制御は含めない。無応答を理由にサービスや宛先を自動で変更しない。
6. 対象2B0/1C3および周辺通信の継続、車両状態、表示警告を確認して終了する。

## 結果の判定

|結果|言えること|言えないこと|
|---|---|---|
|識別応答あり|この経路に読み出しに応答する対象がある|そのECUが2B0/1C3の送信元である|
|707と異なる識別値|異なる識別応答を得た|物理ECUが必ず別である|
|707と同じ識別値|識別値が一致する|同一物理ECU／同じ送信停止仕様である|
|否定応答|その要求・条件で拒否された|識別読み出しや停止機能が全て存在しない|
|無応答|そのバス・要求・観測条件で応答未確認|ECUが存在しない／別バスでも読めない|

新しい実機接続部はまだ実装していない。識別試験を行える状態の確認と、送受信制限・異常時中断・記録の検証が必要。仮に識別できても、その結果だけで送信停止や走行試験へ進まない。
