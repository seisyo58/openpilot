# 特別パターンの入口・出口の詳細調査

2ルートの全受信CANから、走行中（3 km/h以上、ペダル介入なし）の6区間を抽出した。約20Hzの配布用抜粋ではなく、約10ms周期の元フレームを使用。欠損をまたぐ遷移は対象外。CAN間の比較には直前値を使い、補間はしていない。

## 入口の順序

全6例で、1C3の要求値が0から8へ変化した約9～11ms後に、2B0が特別パターンに変わった。従来2518、候補2398という数値名は同じバイト列を指す。

|ルート|入口時刻 秒|1C3が先行 ms|最後のACC OFFから 秒|所有状態|
|---|---:|---:|---:|---|
|59|423.886|9.532|10.888|0xac|
|59|600.416|9.108|72.017|0xac|
|59|670.617|10.993|142.218|0xac|
|59|674.086|10.330|145.687|0xac|
|5a|106.262|10.292|5.759|0xac|
|5a|274.471|9.247|173.969|0xac|

所有状態byte3は全6例で入口前後とも0xACだった。このバイトの切り替えでは、最初の制動だけ通常値が高い現象を説明できない。

ルート59から「走行中、ACC有効、ペダル介入なし、通常状態で1C3が0→正になったら約1周期後に特別パターン」という観測規則を立てると、59の4入口と5aの2入口に対応した。5aの途中の1C3再立ち上がりは、すでに特別パターン中なので新しい入口に数えない。

ただし、1C3と2B0は両方とも純正制御の出力であり、この順序からECU内の因果関係や送信時の制御手順は確定できない。約1周期の差には送信スケジュールも含まれる。1C3の8を要求すれば同じ遷移が起きる、という実験結果はない。

## 出口の順序

全6例で1C3が0になった後も、特別パターンが約11～79ms継続した。

|ルート|通常復帰時刻 秒|1C3のゼロが先行 ms|
|---|---:|---:|
|59|429.066|49.709|
|59|605.856|30.533|
|59|672.826|78.969|
|59|675.137|31.212|
|5a|108.642|10.588|
|5a|278.902|20.494|

従って「1C3が正なら特別、ゼロなら即通常」という同時刻規則には、出口付近で系統的な例外がある。単一の固定遅延も6例に共通しない。出力がゼロになった後の状態継続や別の内部条件が考えられるが、原因は未特定。

## 最初の制動だけ値が高い理由

59の初回は直前5939、5aは6120。その後の4入口は4164～4199。直前1秒の最小値も初回は5128・5325で、単発の飛びでは説明できなかった。初回はACC OFFから約10.9秒・5.8秒後、後続は約72～174秒後だった。

ただし初回2例は車速や先行車・制動履歴も違うため、ACC有効化後の初期状態が原因と断定できない。車速だけ、経過秒数だけ、要求値だけを閾値にした実車用規則を採用する根拠は足りない。未知の符号化や要求の種類の違いも残る。今回、先行車信号やECU内部状態との突き合わせまでは実施していない。

## 停止保持との違い

走行中の6入口は1C3が先行して0→8。停止付近の既知の区間は2B0特別パターンが先行し、約9～11ms後に1C3が0→2だった。さらに停止中のACC開始では、通常要求が非有効のまま1C3が立ち上がる例が両ルートにある。

従って、特別パターンと1C3は一対一の状態ではない。走行制動、停止保持への移行、停止中のACC開始を別の遷移として扱う必要がある。今回確認できた範囲でも、単純な「強い減速要求なら特別値」という実装には情報が不足している。

## 実装への反映

試作の物理変換や閾値は変更していない。入口を決める親の要求は未特定だが、純正が送った要求の観測器では、走行中の1C3立ち上がり、約1周期後の特別化、ゼロ後の遅れた通常復帰を別々に記録できる。

次の識別に有効なのは、同じACC有効期間に複数回の走行制動があるログ、特にe-Pedal OFFとの比較である。これにより初回固有の条件と、e-Pedalに依存する要求の意味を切り分ける余地がある。

詳細数値は leaf_switch_deep_details.json と leaf_switch_exit_details.json。入口の波形は leaf_switch_entry_detail.png。時間は最初のCANを基準とする。

## 波形確認で見つかった追加の符号仮説

59の670.396531秒の6141（005fafac5b005e06）から670.405917秒の4097（ff40b0ac5b006e06）への飛びが確認できた。下位11ビットを2の補数として読むと-3→1となる。通常値を `u = candidate_raw & 0x7ff; signed = u-2048 if u>=1024 else u` と解釈する候補を追加した。先述の「初回だけ高い」はこの符号表現で説明できる可能性があるため、初期化状態の差という仮説より先に検証する必要がある。

この読み方では6入口直前は順に-205、86、68、103、-24、84、出口直後は90、91、89、95、95、89となる。入口はなお一つの閾値にそろわない。特別値・無効値にも同じ物理解釈を適用する根拠はない。単位と正負の物理的意味も未確定。

ルート59の隣接通常フレームで1000超の飛びは、従来候補78件、符号付き11bit候補53件。

ルート5aの隣接通常フレームで1000超の飛びは、従来候補49件、符号付き11bit候補42件。

## 続報：上位ニブルの反転候補

符号付き11bitでは別の境界で飛びが生じるため採用できない。境界バイトを比較すると、通常値の下位部分が増加して桁上がりする瞬間、従来候補に使っていた上位ニブルは減少していた。一方、byte2の上位ニブルは増加していた。

追加候補を `4 * ((byte2 >> 4) * 256 + ((~byte0) & 255)) + ((byte7 >> 2) & 3)` とした。バイト番号は0始まり。これは上位と下位で反転の扱いをそろえ直す解釈である。

同じ所有状態が続く隣接通常フレーム、間隔30ms未満で検証すると、500超の飛びは59で77→0件、5aで49→0件になった。符号付き11bitより通常値全体を滑らかに説明する。単位・ゼロ点は依然未確定。

この読み方の6入口直前は11059、11350、11332、11367、11240、11348。初回2例と後続の差は小さくなるが、一つの入口閾値にはそろわない。したがって初回固有の内部状態があるという推測は優先度を下げ、まず上位ニブルの解釈を訂正した物理校正が必要。

これは通常要求値についての追加仮説であり、固定パターンの呼称や試作の送信用数式を変更したものではない。今回最も大きな進展は、符号仮説の棄却と、両ルートで大きな飛びを解消する上位ニブル候補の発見である。
