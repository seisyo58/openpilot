# 75D UDS通信制御の限定試験

2026-11-04。日本仕様ZE1 e+ G、通常Nissan A。発進を伴わず、P・駐車ブレーキ・フットブレーキ保持で実施する候補。車両の対応・停止範囲は未確認。

1回のREADYで、新鮮な識別値284E76WK2E、通常10 01、拡張10 03を確認。次に28 00 01（通常通信を有効にする候補）に68 00が返り、対象信号・周辺通信が継続する場合だけ28 01 01（通常送信停止候補）を1回送る。

停止要求後はホスト時刻で約30msを受信済み通信の整理区間とし、要求から約130msまで対象2B0/1C3と独立した180/1CB/239の通信を観測。否定・不正応答なら観測を早期終了する。両対象の無送信だけでなく、独立した監視チャネル2種類以上が残ることを必要とする。無応答を肯定応答と扱わない。要求による停止範囲はこの試験で初めて確認する。

その後は再開28 00 01、通常10 01を優先して試す。停止要求を送った可能性があれば、受信・記録エラーや条件変化でも復帰を試す。Panda診断通信所有の条件は維持する。最初の再開要求を試した後に問題が起きた場合も、再開と通常復帰を試す。

最大追加送信は識別1回、条件付きフロー制御1回、通常・拡張各1回、事前の有効化1回、停止1回、再開1回、通常復帰1回の計8 CANフレーム。別バス・別宛先・別サービスへの切替、再送、駆動・制動・操舵・リセット・DTC消去・Tester Presentは含めない。通常起動時FW照会は別に存在する。

停止の意図を保存してから送信し、停止確認中～復帰要求試行中はイベントをメモリに保ち、再開と通常復帰を試した後に保存する。独立したrlogも照合する。保存処理による復帰の遅れを抑える設計であり、ホスト停止や実際のECU停止時間の上限を保証するものではない。

復帰判定は、再開と通常の肯定応答、対象信号の約0.5秒の継続、カウンター進行、事前高頻度チャネルの復帰、記録失敗なしを要求。全結果で通常制御には移行せず、OFFと警告確認・ログ監査まで抑止する。

[udsoncanの一般UDS仕様](https://udsoncan.readthedocs.io/en/latest/udsoncan/services.html#communicationcontrol-0x28)に基づく形式だが、車両の対応を証明しない。再開要求が停止前に受理されても、停止後の確実な復帰は未確認。自動タイムアウト、ホスト停止時の動作、DTC・全ADAS機能への影響も未確認。P2*=5000msを自動復帰時間と混同しない。
