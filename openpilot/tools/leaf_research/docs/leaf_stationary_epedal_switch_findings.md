# 停車中のe-Pedal ON/OFF観測

2026-11-03。対象車はユーザー申告のZE1 e+ G（2022年6月）。生rlogを取得し、CANを観測した。車両への送信・設定変更は行っていない。

## 結論

e-PedalのON/OFF状態を表す有力な2つの信号を特定した。設定状態の識別には有用だが、減速・停止保持の制御要求そのものを特定した結果ではない。

バイト・ビットは0始まり。

|信号|長さ|抽出式|解釈の候補|
|---|---:|---|---|
|bus 0 / 0x2F4|5 bytes|`data[1] & 1`|e-Pedal設定状態（1=ON、0=OFF）|
|bus 1 / 0x2F4|5 bytes|`data[1] & 1`|同じ状態の別バスでの観測|
|bus 0 / 0x5B3|8 bytes|`(data[1] >> 7) & 1`|e-Pedal状態の別メッセージでの表現|

送信元ECU、スイッチ入力からの因果関係、車両がこの信号を制御入力として受理するかは不明。状態ビットを送信すれば機能を切り替えられる、という意味ではない。

## 今回の2本

取得したrlogは1ファイル。CAN記録範囲44.139秒。carStateの速度は全3871サンプルで0、ギヤはparkまたは起動時のunknown。

最初のCAN記録を0秒とした0x2F4の切り替え：

|時刻（秒）|状態候補|
|---:|---|
|14.702|ON|
|22.503|OFF|
|27.103|ON|
|31.723|OFF|
|35.762|ON|
|40.862|OFF|

0x5B3にも同じ6回の切り替えがあり、対応する変化は0x2F4より約10～71 ms後だった。0x5B3の各受信時刻で直前の0x2F4と照合すると441/441フレームで一致。0x2F4はbus 0で2205フレーム、bus 1で2125フレーム。

### 0000005e--44fc03e8de

取得したrlogは1ファイル。CAN記録範囲8.753秒。carStateの速度は全400サンプルで0、ギヤはparkまたはunknown。0x2F4の433フレームと0x5B3の86フレームはすべてOFF候補。今回取得できた範囲には、この2信号の切り替えがない。操作しなかったと断定するものではなく、記録開始・終了やアップロード範囲との関係は不明。

## 過去ログでの独立確認

- e-Pedal ON申告の59：0x2F4が8.678秒でON候補へ、0x5B3が8.728秒でON候補へ。その後走行中の主区間はON候補。
- e-Pedal ON申告の5a：0x2F4が47.093秒でON候補へ、0x5B3が47.122秒でON候補へ。その後、取得済みの走行中区間ではON候補。欠落セグメント内の状態は推定していない。
- e-Pedal OFF申告の5c：全34セグメントの生rlogを再確認。0x2F4は100498/100498フレーム、0x5B3は20098/20098フレームでOFF候補。

この一致から、単なる周期カウンターや一般的な起動状態よりも、e-Pedal設定状態の解釈が強く支持される。メーター映像とのフレーム単位の突き合わせは未実施。

## 既存の制動候補に分かったこと

5dと5eの取得範囲では、いずれも：

- bus 1 / 0x1C3の制動量候補Pは0、byte 5 bit 2のモード候補も0。
- bus 1 / 0x2B0のbyte 4 bit 6の作動候補は0。
- bus 0 / 0x1CBのbyte 4 bit 0とbyte 5 bit 2の保持候補は0。
- bus 0 / 0x1D6の先頭16ビットは12000のまま。

したがって、これらは少なくとも今回のPレンジでのe-Pedal ON/OFF表示を直接表す信号ではない。特に1C3のモード候補と1CBの保持候補を「e-Pedal設定ON」と読み替える根拠はない。

Pレンジではe-Pedalの制動・保持が実作動しないため、今回の結果からDレンジでの保持要求や回生・摩擦の配分要求を否定することもできない。

## 次の解析への用途

追加走行をお願いする前に、過去の生ログへこの設定状態を付け直し、同じルート内のON/OFFや起動前後を区別できる。今回の発見は制御信号の特定よりも、比較条件を明確にして誤解釈を減らす点が大きい。
