# 復旧した未使用区間での固定モデル評価と、要求/応答識別の限界

2026-11-05。原ログ復旧前に固定した通常2B0→0x180モデルを、以前欠けていた5aの4区間で評価した。係数・遅れの再調整、実車送信、制御変更はない。

## 1. 未使用区間でも対応は保たれた

モデルは既存の `leaf_drive_mapping_holdout.json` に保存されていた値をそのまま使用。

```text
D(t + 0.160s) ≈ -0.19905726326136464 * q(t) + 2067.124863628184
```

qは通常2B0の最新候補値、Dは0x180の符号付き12bit候補。学習元は5cの選別済み前半のみで、今回の5aのsegment 5/7/8/11は取得すらしていなかった。

|復旧segment|採用点数|固定モデルRMSE raw|現在の180を維持する予測のRMSE raw|
|---|---:|---:|---:|
|5|209|2.238|9.816|
|7|717|0.774|2.700|
|8|1,149|0.802|2.687|
|11|97|1.094|2.636|
|合計|2,172|1.036|3.976|

全体の誤差平均は+0.108 raw、絶対誤差95パーセンタイルは1.878 raw。qの範囲は9244～10698。連続サンプルは独立した2,172試行ではなく、4つの時系列区間内の観測点。

入力はcarStateの5点ごと。車速3m/s超、ACC有効、ペダル非操作、通常2B0/所有候補0xAC、1C3数値0かつbit2 OFFを要求した。条件を外れる点の前後1.2秒、受信/送信要求でボタンbitが立つ各時刻の1秒前～5秒後を除いた。装置独自の押下か推定せず、両方の全押下を保守的に除外した。

CANは直前30ms以内だけで照合し、補間しない。遅れ先Dもt+160ms以前の直前値で、最大30msの時刻差を許容する。区間の両端から1.2秒を除き、遅れ先も復旧segment内に収めた。選別ルールは結果に対する学習ではないが、後ろ向きに定義した観測選別である。

[check_recovered_holdout.py](../check_recovered_holdout.py)で[監査JSON](../evidence/leaf_recovered_holdout_20261105.json)を再現できる。既存モデルの係数や遅れを探索するコードは含めていない。

## 2. 高い対応から言えることと、言えないこと

現在の180値を維持する基準よりも、160ms前のqからの固定モデルが良い。単に平坦な時系列を比べただけではなく、qが180の変化に先行する対応を別の区間でも確認した、という追加の根拠になる。

それでも次の2仮説は、この記録では区別できない。

|仮説|今の観測と両立する理由|識別に不足するもの|
|---|---|---|
|180は駆動系の実応答を含む|指令候補qに遅れて比例する実応答でも同じ関係を作れる|独立した校正済み実トルク・電流・電力等|
|180は要求の変換・フィルター後の反映|遅延/フィルターされた要求値でも同じ関係を作れる|要求量と測定量を区別する仕様、独立した実応答との比較|

車体加速度やIMUは総力の結果であり、勾配・抵抗・摩擦ブレーキ・他の補正が混ざる。その結果との相関だけでは、180がどこで何を測るかを一意に決められない。今回の低誤差を物理単位・ゼロトルク点・CAN指令の受理確認へ置き換えない。

同じ理由で、1C3を摩擦専用とするモデルと、全体的な協調制動の量とするモデルの区別にも、実回生・油圧等が必要になる。既存の[条件合わせとIMU照合](leaf_matched_braking_and_imu_findings.md)は仮説の優先順位を変える材料だが、物理収支を閉じる証拠ではない。

## 3. 直接検証できる信号が増えたか

復旧後3走行の原CAN全件の件数でも、既知EV-CAN候補ID 1D4/1D5/1DA/1DB/1DC/55B/5BC/5C0は全て0。旧5aで欠けていた区間にも記録されていなかった。メーカーの数値ID定義や単位を確定したものではないが、少なくとも既知EV-CAN候補を使った直接比較の入力は今回もない。

carState.fuelGauge/regenBrakingの既定値や、1CBを独立実測と仮定して不足を埋めない。ECO、SOC、回生可能上限も確定していない。

## 4. この論点の打ち切り判断

追加の回帰やフィルター調整は可能だが、要求の反映と実トルクを区別する新しい観測を作るものではない。ここでは、復旧した未使用区間での固定評価までで受信モデルの追加確認を終える。

既存の[ジャイロ検証](leaf_bounded_gyro_check.md)も、事前に限った3区間で改善が安定しなかったため打ち切ったもの。今回、それを再調整・拡大していない。0x292やIMUの一致を良くすることと、駆動/摩擦/回生の物理配分を識別することは別の問題。

再開に価値があるのは、独立した実モータートルク・電流・電力/油圧の記録、該当ECUの信号仕様、またはそれらに結び付く新しい一次情報が得られた場合。追加機器の購入や接続変更は今回行っていない。

```sh
.venv/bin/python -m openpilot.tools.leaf_research.check_recovered_holdout \
  /path/to/reextracted/0000005a--34bc682d3e.npz \
  --metadata /path/to/reextracted/0000005a--34bc682d3e.json \
  --out /tmp/leaf-recovered-holdout.json
```
