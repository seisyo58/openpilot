# 診断セッションを示す通常CAN信号の探索

対象は保存済みの生rlog。新たな車両への送信・設定変更は行っていない。

## 結果

通常CAN上で、診断セッションに追従して安定して1→3→1となる独立した信号は見つからなかった。診断応答0x77Dの50 01 / 50 03 / 50 01は記録されているが、これは要求に対する肯定応答であり、セッション状態の継続配信ではない。

## 方法と範囲

- route67（00000067--538973cf93）: 拡張要求の2秒前から通常復帰応答の2秒後まで、CAN bus0/1/2、ID 0x001〜0x6FFの138チャネル、28,946フレームを読んだ。チャネルはbus・ID・長さの組み合わせであり、独立した138種類の信号を意味しない。
- route68（00000068--32fe1f4a1e）: 同じ範囲で138チャネル、27,423フレーム。
- 診断要求・応答そのものと送信エコーは探索対象から除外。
- 切り替え前・拡張中・通常復帰後の各区間に3フレーム以上あるチャネルについて、各ビットが安定して反転・復帰するかを探索。さらにリトル／ビッグエンディアンの連続2ビットが1→3→1になるかを調べた。これは任意のDBCレイアウト、符号化、非連続ビットの全探索ではない。
- 前区間は要求前0.5秒と、通常セッション肯定応答後に限定した区間の2種類。境界から0/10/30/50msを除外した条件も比較した。

## 候補の棄却

route67の一部の狭い区間だけで0x2AAのbyte5 bit0（0起算）が0→1→0となった。bus0/1/2で同じ内容が観測されるため、3個の独立した候補ではない。

しかし、このビットはroute67のセグメント全体で87回変化しており、切り替え前にも頻繁に変化する。route68では拡張セッションへの移行から通常復帰まで1のままで、切り替えに追従しない。したがって、診断セッションを示す信号としては採用できない。route69（F186要求のみでセッション変更なし）でもセグメント全体で31回変化した。

## 限界

route67で拡張セッション肯定応答から通常復帰要求までは約304ms、route68は約72msしかない。route68は最初の通常セッション肯定応答から拡張要求まで約8msしかなく、この区間を厳密な比較元にすると3フレーム条件を満たすチャネルがない。低周期信号・遅延通知・未記録の別CAN・異なる符号化の可能性は残る。信号が存在しないと証明した結果ではない。

今回のF186試験route69は初回読み出しで7F 22 31となり、1→3→1の切り替え自体を実施していない。このルート単独からは切り替えとの相関を判定できない。

## 次の検証の価値

継続状態が必要なら、次回は既に成功したセッション切り替えだけで、拡張状態を数秒保持し、その後通常へ戻して記録すると低周期信号を比較しやすい。現時点では準備・予約・実施していない。通信停止や制動要求を含める必要はない。
