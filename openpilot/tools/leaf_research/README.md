## 内容

- `docs/`: 調査文書と試験結果。古い仮説・準備計画も履歴として保存している。各文書の日付と後続の訂正を確認し、古い「次の試験」や準備完了を現在の実施指示とは扱わない。
- `dbc/leaf_longitudinal_candidates.dbc`: Cabanaなどで使う独立した観測用DBC。候補・旧解釈もコメント付きで残る。車両用DBCへの置換・送信用定義ではない。
- `monitor.py`: 既存の受信専用モニター。通常のopenpilotと別プロセスで明示起動する。公開・送信・Params変更の機能はない。
- `evidence/`: 主要な監査結果とDBC照合結果。元のrlog・個人の走行ログは含めない。
- `provenance.json`: 元ファイル、コピー先、SHA256、基点と実験ブランチの版。

文書内の`outputs/`や`work/`、絶対ローカルパスは元の調査ワークスペースを指すものがある。同名の文書はdocs、採録したJSONはevidenceで確認できる。全ての元ログ・中間生成物を再配布した完全な再現環境ではない。

## モニターの利用

openpilotのPython環境で、必要なときだけ明示的に起動する。

```sh
python openpilot/tools/leaf_research/monitor.py record --input none --duration 60 --out /tmp/leaf-observation.jsonl
```

このモニターは約20Hzの状態スナップショットで、全CANを欠落なく記録するロガーではない。CAN消失や厳密な周期の判定には元のrlogを使う。既存出力ファイルは上書きしない。

既存モニターにはキーボード／ゲームパッドの仮想比較機能も残るが、入力は記録内の表示用で、車両への要求にはならない。加速度への物理変換や操作許可を表さず、`transmit_allowed`は常にfalse。

```sh
python -m unittest discover -s openpilot/tools/leaf_research/tests
```

診断試験の再実行や縦制御をこの保存ブランチから有効にする機能はない。
